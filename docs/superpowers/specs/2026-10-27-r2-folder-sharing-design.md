# R2 資料夾分享頁設計規格

**日期：** 2026-10-27  
**狀態：** 已完成逐節設計確認，待審閱正式規格  
**部署目標：** Cloudflare Pages + Pages Functions + R2 binding（Workers Free）

## 1. 目的與範圍

讓部落格提供一個指向 R2 指定目錄的分享頁網址。訪客可在同一頁瀏覽該分享根目錄以下所有符合規則的多層檔案，以公開 R2 網址存取個別檔案，並閱讀頁面下方渲染的 Markdown 說明。管理員透過 R2 Bucket 根目錄的單一純文字規則檔管理哪些目錄可以建立分享頁；內容更新後，分享頁於下一次請求即直接反映當時 R2 的狀態。

整套服務唯讀。沒有上傳、管理後台、使用者登入、個別內容發佈、預先建立索引或預先壓縮檔的流程。Pages 程式本身仍須正常部署；部署時可決定是否啟用 ZIP 下載。

### 1.1 內容規模

分享目錄通常少於 10 個檔案，預期不超過 100 個。未另外設定人為檔案數硬上限，執行時仍受 Cloudflare Free 資源限制約束。列舉必須正確處理 R2 分頁，不能假定單次回應就包含全部物件。

## 2. 已確認的選擇

- 以 Cloudflare Pages Functions 直接產生完整 HTML；樹狀清單以原生 `<details>` 展開或收合，不需要前端 JavaScript。視覺主題見 [分享頁 UI 主題設計規格](2026-10-27-ui-theme-design.md)。
- Bucket 既有公開網址維持開放。單檔連結、Markdown 圖片與其他合法相對資源使用 R2 公開網址，不經 Functions 代理。
- 以允許清單的反轉 `.gitignore` 語意管理分享根目錄。預設拒絕；一般規則允許，`!` 排除。
- 精確目錄規則只核准該目錄擁有分享頁；`/**` 類型規則可核准該目錄及子目錄各自擁有分享頁。
- 分享頁使用可展開的樹狀清單；頁面底部顯示 README。
- `README.md` 優先於 `.README.md`；只選用分享根目錄中的檔案。
- ZIP 功能部署預設停用；啟用時只產生無壓縮 ZIP STORE 串流，不使用 DEFLATE 或其他壓縮方法。
- README 的原始 HTML 支援屬選用項目，以套件是否容易安全處理為準。

## 3. 對外網址與部署設定

對外分享頁使用 `/share/<bucket-relative-directory>/`，例如 `/share/releases/project-a/`。ZIP 下載端點使用獨立的 `/api/share-zip?dir=releases%2Fproject-a`，由伺服器依相同授權機制判斷；其精確路由名稱可在實作計畫中調整，但不得與分享頁的實際 R2 物件名稱衝突。

部署設定包含：

| 設定 | 用途 | 預設 |
| --- | --- | --- |
| R2 binding `BUCKET` | 列舉及讀取 Bucket 物件 | 必須設定 |
| `R2_PUBLIC_BASE_URL` | 既有 R2 公開檔案網域 | 必須設定，固定可信的 HTTPS 網址 |
| `ENABLE_ZIP_DOWNLOAD` | 是否顯示「下載全部」並啟用 ZIP 端點 | `false`；僅字串 `true` 啟用 |
| `SHARE_RULES_KEY` | 規則物件鍵名 | `.r2-share-rules` |
| `FOOTER_HTML` | 頁尾的單行 HTML，原樣渲染；只限管理者輸入的受信任內容 | 未設定，不顯示頁尾 |

以上設定由部署環境管理：正式環境在 Cloudflare 後台設定，部署時不需修改儲存庫中的任何檔案。版控中的 `wrangler.toml` 只供本機開發使用，刻意不含 `pages_build_output_dir`，避免它成為 Pages 專案設定的唯一來源。ZIP 開關屬部署設定，R2 檔案及分享規則則在每次相關請求重新讀取，無須重新部署程式。

## 4. 規則檔與授權語意

Bucket 根目錄的 `.r2-share-rules` 是單一 UTF-8 純文字物件。只由管理員修改。規則採用 `.gitignore` 類似的行規則、註解、跳脫字元與 glob 比對，但**授權方向反轉**。所有規則都以 Bucket 根目錄為基準，不接受藉由路徑跳脫或絕對 URL 改變基準。

```gitignore
# 精確核准 project-a 的分享根目錄
releases/project-a/

# 核准 project-b 與其所有子目錄各自成為分享頁
releases/project-b/**

# project-b/private 與其後代不出現在分享頁與 ZIP
!releases/project-b/private/
```

### 4.1 必須遵守的規則

1. 預設拒絕建立任何分享頁。沒有正向規則可比對的分享根目錄回應 `404`。
2. `releases/project-a/` 核准該精確目錄作為分享根目錄，其下的多層檔案可在該頁瀏覽；不因此授予子目錄獨立分享頁網址。
3. `releases/project-b/**` 核准該目錄與未排除的後代目錄作為分享根目錄。
4. `!` 規則排除指定目錄及後代。被排除目錄的物件不列入檔案樹、不納入 ZIP，也不可作為分享頁根目錄。
5. 規則依序處理，並採用 gitignore 風格的最後適用規則優先。即使更深路徑另有允許規則，仍須符合未被排除的祖先目錄條件，避免穿透明確排除的父目錄。
6. 與 `.gitignore` 相同，支援 `*`、`?`、`**`、字元集合、註解與跳脫。實作時應採用有測試的 glob 函式庫或建立相容性測試，並保留上述 `/` 與 `/**` 的分享根目錄語意。
7. 規則檔本身不可列在任何分享清單或 ZIP 中。規則檔不包含機密；因為 Bucket 已公開，知道其公開物件網址的人仍可能直接讀取它。

「建立分享頁的授權」與「內容可列出範圍」分別判斷。先檢查請求的分享根目錄獲准，再限制所有列舉與讀取只在該分享根目錄以下；對每一個物件鍵還須再次套用排除規則。

## 5. 路徑處理與安全邊界

伺服器必須使用統一的路徑解析與授權模組，供頁面、README 資源連結、ZIP 端點共用。

- 只接受 Bucket 相對目錄。原始 URL 與解碼後的路徑均需檢查，拒絕空的異常區段、`.`、`..`、反斜線、空位元組、重複或混用編碼造成的分隔符混淆；避免二次解碼造成的路徑逃逸。
- URL 每個合法路徑區段分別編碼。R2 物件鍵以可信的標準化目錄區段組合，不把未驗證字串直接接到 `list(prefix)`。
- R2 列舉前綴固定為已授權分享根目錄加尾端 `/`，例如 `releases/project-a/`；不可改成 `releases/`、Bucket 根目錄或其他祖先。額外檢查回傳的每個鍵是否真的位於該邊界內。
- 以路徑區段及 `/` 邊界判斷從屬關係，避免 `project-a/` 誤比對 `project-a2/`。
- README 中相對圖片及檔案連結以**目前分享根目錄**為基準解析。合法資源可轉為公開 R2 URL。若 `../` 等解析結果離開分享根目錄，或指向被排除的物件，該相對資源連結須移除或以無法存取狀態呈現。
- Markdown 中正常的外部 HTTPS 連結可照原樣呈現。`javascript:` 等可執行連結協定不得成為分享頁中的可執行連結。
- 如果啟用原始 HTML，至少須能檢查及轉換 `<img src>`、`<a href>` 等資源 URL，並處理事件屬性及危險協定；套件無法可靠處理時，停用原始 HTML 支援。此功能列為選用項目。
- HTML 標題、物件名稱、檔案大小及其他動態內容均須經正確輸出編碼。公開 R2 物件的存取權不受本功能影響，分享規則無法限制既有的物件直連。

## 6. 分享頁產生流程

1. 接收 `GET /share/<directory>/`，驗證網址並由規則檔確認分享根目錄資格。
2. 以該根目錄的 R2 前綴執行 `list()`，依 `truncated` 與 `cursor` 繼續取得剩餘物件；不得用「回傳筆數少於 limit」判斷已完成。
3. 套用規則排除與邊界檢查；利用完整的相對路徑在記憶體建立單頁樹狀結構。顯示可展開或收合的目錄層級及個別檔案連結。
4. 僅在目前分享根目錄讀取 `README.md`，若不存在才讀取 `.README.md`。兩者同時存在時優先顯示前者。若都不存在，省略 README 區塊。
5. 將 Markdown 在伺服器轉為 HTML，解析合法相對圖片及檔案網址，並在同一份 HTML 回應的檔案清單下方呈現。
6. 訪客開啟檔案連結時直接前往既有 R2 公開網域。是否下載或在瀏覽器內預覽，取決於原物件的 HTTP 回應標頭與瀏覽器。

每次訪問均以當下讀取結果產生頁面；不使用需要額外發佈的靜態快照。對分享頁 HTML 設定禁止持久快取或合適的重新驗證策略，避免 CDN 快取使已變更的分享規則長時間不生效。

## 7. 選用的即時 ZIP 下載

部署開關 `ENABLE_ZIP_DOWNLOAD` **預設關閉**。停用時，HTML 不顯示「下載全部」，ZIP 端點亦回應 `404`。啟用後，端點先重新讀取規則、授權根目錄、列舉與驗證當下的檔案，再傳送下載回應。

使用 ZIP 格式的 **STORE（compression method 0）**，從 R2 逐檔讀取原始位元組，寫入可逐塊輸出的 ZIP 串流。禁止壓縮演算法、完整檔案記憶體緩存、中間 ZIP 物件、預先產生 ZIP 或其他備援壓縮方式。每個 ZIP 項目使用相對於分享根目錄的合法路徑，保持多層目錄結構，包含未被排除的 README；不得建立 `../` 或絕對路徑項目。

ZIP 寫入器需支援串流所需的 CRC-32、資料描述符、中央目錄，以及在檔案或彙整大小超出標準 ZIP 欄位時採用 ZIP64。啟用時應選用與 Workers Streaming API 相容、實際產出 method 0 的套件，並以解壓測試驗證。

在送出 ZIP 回應前，盡可能完成授權與列舉檢查。R2 物件若在列舉與串流期間被更新或刪除，該次下載可能失敗；不承諾跨多個物件的原子快照。串流開始後發生讀取錯誤，應中止串流並記錄伺服器日誌，不回傳看似完成的損壞 ZIP。

### 7.1 Free 方案的操作限制

截至 2026-10-27，Cloudflare Workers Free 每次 HTTP 請求 CPU 預算為 10 ms、記憶體上限為 128 MB、每日最多 100,000 次 Workers 請求。Cloudflare 服務內部子請求在 Free 方案有另外的 1,000 次額度；對外子請求為 50 次。大型 ZIP 仍可能因 CPU 預算、記憶體、平台其他限制或連線中斷而失敗。串流降低記憶體用量，但不免除 CRC-32 計算的 CPU 成本；需以真實檔案進行 Free 環境驗證。

## 8. 失敗處理

| 狀況 | 行為 |
| --- | --- |
| 規則檔遺失、無法解析或讀取失敗 | 預設拒絕，公開回應不包含 Bucket 內部資訊 |
| 分享根目錄未授權或不存在 | 回應 `404` |
| URL 異常、路徑跳脫或越界 | 拒絕請求，不執行不合法的列舉 |
| 分享目錄合法但沒有檔案 | 顯示空目錄訊息 |
| 沒有 README | 不顯示 README 區塊，檔案清單繼續可用 |
| ZIP 開關關閉 | 隱藏按鈕，直接請求 ZIP 端點回應 `404` |
| R2 暫時故障 | 回應通用錯誤頁，細節只記錄伺服器日誌 |
| ZIP 串流開始後物件讀取失敗 | 中止回應串流並記錄錯誤 |

## 9. 模組邊界

- `rules`：載入及解釋規則，回傳分享根目錄授權及內容排除判斷。
- `paths`：單一權威來源處理 URL、R2 鍵名及 Markdown 相對資源解析。
- `listing`：限制前綴列舉、分頁、排除過濾及樹狀資料建構。
- `readme`：README 選擇、Markdown 渲染與資源 URL 處理。
- `html`：將必要資料轉成 HTML、可展開樹狀清單及選用的 ZIP 按鈕。
- `zip-stream`：只有 ZIP 開關啟用時，按授權結果串流輸出 STORE ZIP。
- `routes`：Pages Functions 的路由及錯誤回應，依賴上述模組；不重複實作授權。

模組介面、第三方函式庫與檔名可於實作計畫中細化，但不得改變已核准行為。

## 10. 驗收條件與測試

- 精確目錄規則能分享該根目錄下的多層檔案；直接開啟未獲授權子目錄分享網址回應 `404`。
- `/**` 正確開放該目錄及其後代分享頁；被 `!` 排除的目錄與物件不出現在任何分享頁或 ZIP。
- 無規則、規則檔損壞、規則檔不存在及 R2 錯誤均採取預設拒絕或受控錯誤回應。
- URL 攻擊案例涵蓋 `../`、`%2e%2e`、`%2F`、`%5C`、雙重編碼、重複分隔符與相似字首目錄；不觸發父目錄列舉。
- README 選用順序正確；相對圖片與檔案連結維持分享根目錄內的解析結果；越界或被排除資源不產生分享站可用連結。
- HTML 輸出可安全處理特殊檔名。若實作原始 HTML，另測試危險連結協定、事件屬性與相對圖片來源。
- 加入、刪除或更新 R2 物件，以及修改分享規則後，重新載入頁面可觀察到更新，無需額外內容發佈。
- R2 `list()` 分頁案例不遺漏物件，也不會無限迴圈。
- ZIP 預設關閉時按鈕與端點都停用；明確啟用後，產出的 ZIP 可解壓、使用 method 0、保留正確路徑、包含 README 且沒有被排除檔案。
- ZIP 測試涵蓋空目錄、檔案於列舉後消失、串流途中失敗、大檔案與 ZIP64 邊界。正式環境需驗證 Workers Free CPU 預算下的實際可行規模。

## 11. 非目標與風險

本版沒有使用者登入、上傳、權杖分享、下載次數限制、密碼保護、管理後台、可搜尋 Bucket 全域檔案的目錄頁或私有 R2 的存取控制。分享規則只限制**本站提供的分享頁與 ZIP 入口**；由於 Bucket 已有公開網域，知道原始物件 URL 的訪客仍可能直接讀取檔案。

對極大型 ZIP 的可靠性不作承諾。Free 方案 CPU 限制可能使此選用功能實際可用規模比預期檔案數更低。原始 HTML 僅在套件容易支援必要 URL 攔截與安全處理時納入。
